# Plan 02-01 — Parallel container `aiostreams-jf` on the Dubai VPS

## Facts (verified 2026-09-08, read-only)
- VPS `ubuntu@145.241.123.188` (key `~/.ssh/ssh-key-2026-06-13.key`), aarch64, Docker 29.7. Production container `aiostreams` (image `ghcr.io/viren070/aiostreams:latest` = 2.34.0), compose project `apps-hetzner`, file `/home/ubuntu/apps-hetzner/docker-compose.yml`, data bind `/home/ubuntu/apps-hetzner/data/aiostreams` → `/app/data`, network `web`, Traefik router `aiostreams-dxb` (Host `aiostreams-dxb.tweakstreams.stream`, entrypoint `websecure`, certresolver `letsencrypt`, port 3000, middlewares `aio-compress-dxb` + a `scanner-…` middleware).
- DNS `jf.tweakstreams.stream` → 145.241.123.188 (created by Maged).
- Repo default branch `release` = v2.34.0 + Jellyfin layer; Dockerfile at repo root; layer mounted at `/jellyfin`; `ENABLE_JELLYFIN_API` defaults true.

## Steps
1. **Clone + build on the VPS (native arm64).** `git clone -b release https://github.com/tweakapps/aiostreams-jf-update.git /home/ubuntu/aiostreams-jf/src`; `docker build -t aiostreams-jf:2.34.0-jf1 /home/ubuntu/aiostreams-jf/src`. Record image id and build time. (GHCR push, DEP-01: after a successful local build, attempt `docker login ghcr.io -u tweakapps --password-stdin` using a token the orchestrator provides via `gh auth token` piped over SSH stdin — never written to disk or logs; then `docker tag … ghcr.io/tweakapps/aiostreams-jf-update:2.34.0-jf1 && docker push`. If login is not possible, record DEP-01 as deferred and continue; the local image is enough for Phase 2.)
2. **DB copy.** Production data stays untouched. Copy `/home/ubuntu/apps-hetzner/data/aiostreams` → `/home/ubuntu/aiostreams-jf/data` with `cp -a`; if a sqlite DB file is present and `sqlite3` is installed on the host, prefer `sqlite3 <src> ".backup '<dst>'"` for the DB file itself for consistency. Record file list sizes (no contents).
3. **Compose (separate project).** Write `/home/ubuntu/aiostreams-jf/docker-compose.yml` with service `aiostreams-jf`: image `aiostreams-jf:2.34.0-jf1`, `restart: unless-stopped`, `networks: [web]` (external), volume `/home/ubuntu/aiostreams-jf/data:/app/data`, environment = the production container's environment copied verbatim from `docker inspect aiostreams` (keep `SECRET_KEY` identical — it decrypts the copied profiles; keep `DATABASE_URI`, `BUILTIN_NZBHYDRA_URL`, `BUILTIN_STREMTHRU_URL`, proxy/OIDC/usenet vars) EXCEPT: `BASE_URL=https://jf.tweakstreams.stream`, `ADDON_NAME` suffixed ` JF`, `ADDON_ID` suffixed `-jf`, `ENABLE_JELLYFIN_API=true`, `PORT=3000`. Put the environment in `/home/ubuntu/aiostreams-jf/.env` (chmod 600) referenced by `env_file`, never echoed to the terminal or logs. Traefik labels mirroring production with router/service/middleware names suffixed `-jf` and `Host(\`jf.tweakstreams.stream\`)`; include the compress middleware; do NOT attach the `scanner-…` middleware (Jellyfin clients cannot pass interactive auth) — note it.
4. **Start + verify.** `docker compose up -d` in `/home/ubuntu/aiostreams-jf`; wait for healthy; from the VPS: `curl -s http://<container>:3000/jellyfin/System/Info/Public` (via `docker exec` or the web network) → 200; from the Mac orchestrator side the executor reports; then via Traefik: `https://jf.tweakstreams.stream/jellyfin/System/Info/Public` → 200 with a valid cert, `https://jf.tweakstreams.stream/stremio/u/maged-dxb/manifest.json` → 200 (profiles present in the copied DB). Confirm the production container is unchanged: `docker ps` shows `aiostreams` still Up with the same started-at time; `/home/ubuntu/apps-hetzner` untouched (`git status`-like check: mtime of the compose file and data dir before/after).
5. **Rollback doc (DEP-03).** `/home/ubuntu/aiostreams-jf/README.md`: how to stop/remove the parallel stack, where the DB copy is, that production was never modified; plus the future cut-over recipe (retag production to the jf image, keep `ghcr.io/viren070/aiostreams:latest` digest recorded for rollback).
6. **Summary** ≤25 lines in `.planning/phases/02-parallel-deploy/02-01-SUMMARY.md`: image id, DB copy size, hostname checks, what was deferred; commit + push (`release`).

## Hard rules
- Never `docker compose down/restart` in `/home/ubuntu/apps-hetzner`; never write there. Never print env values (only variable names). Never kill any process.
- If the build fails on the VPS (memory/CPU), STOP with a checkpoint (options: build on the Mac with `docker buildx --platform linux/arm64` and push to GHCR).
