# Plan 05-03 — Cast photos and roles, person images, image-relay diagnostics, single media-source stub

## Why
- Infuse shows the cast row empty or with blank avatars. `peopleFrom()` (`dto.ts:272-294`) emits `People` with Name/Id/Type only — no `PrimaryImageTag`, no `Role`. Infuse only renders a photo when `PrimaryImageTag` is present and some builds hide the row when no entry has one.
- Even with the tag, `/Items/{personId}/Images/Primary` would 404: `imageUrlFor()` (`playback.ts:441`) rejects kinds outside `ARTWORK_KINDS = {movie, series, season, episode}` and nothing ever remembers a person image.
- AioMetadata already sends photos: `meta.app_extras.cast` is an array of `{ name, character, photo }` (verified in the running aiometadata container, `parseProps.js` ~line 963). The AIOStreams `MetaSchema` is `.passthrough()`, so `app_extras` survives into `ParsedMeta` — it is simply ignored.
- Image relay 502s (7 of 23 in the log window) are logged at `debug` with no URL, so posters vanish undiagnosed.
- `stubMediaSources()` (`dto.ts:320-352`) attaches **two** fake `Protocol:'File'` sources ("X" and "X (2)") with empty `MediaStreams` to every Movie/Episode list item; the likely cause of the tvOS version-picker oddities.

## Steps

### 1. Cast from `app_extras` — `packages/core/src/jellyfin/dto.ts`
Rewrite `peopleFrom(meta)` and give it the build context (`peopleFrom(ctx, meta)`; update the one call site at ~line 500):
- Read `const extraCast = Array.isArray((meta as any).app_extras?.cast) ? (meta as any).app_extras.cast : []` — entries may be `{ name, character, photo }` or plain strings; normalise defensively (`name` required, skip otherwise).
- Build people in this priority: `app_extras.cast` (Type `Actor`, `Role: character` when present), then fall back to `meta.cast` / links `Cast` only for names not already present (dedupe by lower-cased name). Directors/Writers unchanged, but also check `app_extras.director(s)` / `app_extras.writers` arrays (AioMetadata emits both spellings) before the links fallback.
- For every person with a non-empty `photo` URL: `rememberImages(ctx.uuid, personId, { Primary: photo }, true)` and set `PrimaryImageTag: imageTag(photo)` on the People entry. `personId = encodeJellyfinId({ k: 'person', n: name })` (already what `push` does).
- Cap at 30 people per item (Infuse renders ~20).
- Type the People entry as `{ Name; Id; Type; Role?; PrimaryImageTag? }`.

### 2. `buildPersonItem` — `dto.ts:414-428`
Accept an optional `photo?: string`. When given, remember it and set `ImageTags: { Primary: imageTag(photo) }`. Callers in `items.ts` (`itemFromDescriptor` case `'person'`, `/Persons/:name` in library.ts) pass nothing today; that is fine — the image route will find the remembered photo from the movie/series build. Add `PrimaryImageAspectRatio: 0.6667` for person items.

### 3. Person images through the relay — `packages/server/src/routes/jellyfin/playback.ts`
- Add `'person'` to `ARTWORK_KINDS` (~line 372) so `imageUrlFor()` reaches the remembered-image path. For persons there is no `rebuildImages` source and no metahub fallback: after `recallImages` misses, return `null` (404) — do **not** call `rebuildImages` for `d.k === 'person'`.
- Also handle the id normalisation: person ids are hashed ids (`b2…`); `decodeJellyfinId` resolves them through the DB mapping, which is populated by `encodeJellyfinId` when the movie was built — so ordering is fine.

### 4. Image relay diagnostics and fallback — `playback.ts:457-507`
- Raise the catch log (`~line 498`) from `debug` to `warn` and include `{ url: result.url, itemId, type }`.
- When `upstream.status >= 400` (line ~477), do not forward the upstream status: if `result.public` is false and a metahub fallback exists for the descriptor (`metahubImageUrl`), `302` to it; otherwise respond `404` (Jellyfin clients handle 404 as "no image" gracefully, but treat 502 as an error).
- Make `HEAD` (`~508-524`) mirror the same resolution: 200 only if `imageUrlFor` resolves, else 404.

### 5. One stub media source — `dto.ts:320-352`
Return a single stub (drop the `(2)` entry). Search for any code that relies on two entries (e.g. `playback.ts` `resolveStreamTarget`, `stub2`) with `grep -rn "stub2\|MediaSources\[1\]" packages` and adjust so a single default source still resolves.

### 6. Tests — new `packages/core/src/jellyfin/dto.test.ts`
Using the existing vitest setup (see `ids.test.ts`, `images.test.ts` for the pattern):
- `peopleFrom` with `app_extras.cast = [{name:'A', character:'X', photo:'https://p/a.jpg'}]` yields one Actor with `Role:'X'` and a `PrimaryImageTag`, and `recallImages(uuid, personId)` returns the photo.
- Fallback: `cast: ['B']` with no app_extras yields Actor B without `PrimaryImageTag`.
- `stubMediaSources` returns exactly one entry.

### 7. Build + test + commit
- `pnpm build`; `pnpm --filter ./packages/core test` (50 + new tests green).
- Commit: `feat(jellyfin): cast photos and roles from AioMetadata, person images via relay, relay diagnostics, single media-source stub`; push `release`.

## Hard rules
