# Plan 05-01 — Dedicated Jellyfin rate limit + catalog error isolation

## Why (from the 2026-09-08 audit)
Infuse tvOS draws one home row per library and fires one `/Users/{uid}/Items/Latest` (+ one `/Users/{uid}/Items`) per library in parallel: 48 requests in ~1 s for 24 libraries. `routes/jellyfin/index.ts:36-51` routes those through `stremioCatalogRateLimiter` (30 req / 5 s / IP, `core/config/schema/rate-limits.ts:115-119`), so ~20 per burst get a 429 with a Stremio-shaped body, which Infuse shows as "An error occurred". Mac Infuse fetches one library at a time and never trips it.

Separately, single-catalog browse routes turn one throwing `getCatalogPage` into a 500 for the whole row, and `jf()` returns the raw error message to the client.

## Steps

### 1. New limiter config — `packages/core/src/config/schema/rate-limits.ts`
Add, next to `stremioCatalog` (~line 115), a new entry using the same `rateLimit({...})` helper:
```ts
jellyfinBrowse: rateLimit({
  windowDefault: 5,
  maxDefault: 300,
  envPrefix: 'JELLYFIN_BROWSE',
  label: 'Jellyfin browse',
}),
```
(Keep the existing `stremioCatalog` untouched — it still protects the public Stremio surface.)

### 2. Device-aware limiter — `packages/server/src/middlewares/ratelimit.ts`
- `createRateLimiter` currently keys by IP only (`keyGenerator`, ~line 41-45). Extend its signature with an optional `keyExtra?: (req: Request) => string | undefined`. When present and it returns a non-empty string, the key becomes `prefix + ':' + ipKey + ':' + extra`.
- Add `jellyfinBrowseRateLimiter = lazyLimiter(() => appConfig.rateLimits.jellyfinBrowse, 'jellyfin-browse', keyExtra)` where `keyExtra` parses the `DeviceId` from `Authorization` / `X-Emby-Authorization` (`MediaBrowser … DeviceId="…"`). Import and reuse `parseMediaBrowserHeader` from `../routes/jellyfin/context.js` — if that creates an import cycle, move `parseMediaBrowserHeader` into a tiny new file `packages/server/src/routes/jellyfin/mediabrowser.ts` and import it from both places (context.ts keeps re-exporting it so nothing else breaks). Fallback: `req.query.api_key` prefix (first 12 chars) when no header, else undefined (IP-only).
- Update `lazyLimiter` to pass `keyExtra` through to `createRateLimiter`.
- Export `jellyfinBrowseRateLimiter` from the module's export list (~line 175).

### 3. Use it and fix the 429 body — `packages/server/src/routes/jellyfin/index.ts`
- Import `jellyfinBrowseRateLimiter`; in the classifier (~line 41-51) replace `stremioCatalogRateLimiter(req, res, next)` with `jellyfinBrowseRateLimiter(req, res, next)`. Remove the now-unused `stremioCatalogRateLimiter` import.
- Also route `/Users/:id/Items/:itemId` (single-item detail, `/^\/(Users\/[^/]+\/)?Items\/[^/]+$/i`, excluding `PlaybackInfo|MediaSources|Images`) through `jellyfinBrowseRateLimiter` rather than `staticRateLimiter` — Infuse fetches item detail for every tile on a row.
- 429 body: the limiter `handler` throws `APIError(RATE_LIMIT_EXCEEDED)` which the app's error middleware renders in Stremio shape. Inside `createJellyfinRouter()`, add an error-handling middleware **after** the limiter selection middleware and before `jellyfinContext`:
  ```ts
  router.use((err, req, res, next) => {
    if (err instanceof APIError && err.code === constants.ErrorCode.RATE_LIMIT_EXCEEDED) {
      res.status(429).json({ Message: 'Too many requests, please slow down' });
      return;
    }
    next(err);
  });
  ```
  (`APIError`, `constants` from `@aiostreams/core`. Express error middleware must have 4 args.) Verify the limiter's thrown error actually reaches this middleware; express-rate-limit calls `handler` synchronously inside the middleware, and express 5 forwards thrown errors to the next error handler. If on inspection the throw is caught elsewhere first, instead pass a custom `handler` for the Jellyfin limiter that writes the JSON 429 directly.

### 4. Generic 500 + headersSent — `packages/server/src/routes/jellyfin/context.ts`
In `jf()` (~line 448-458): keep the `logger.error` with the real message, but send `res.status(500).json({ Message: 'Internal server error' })`. Replace `else next(error)` with `else res.end()` guarded by `if (!res.writableEnded)` — the router's 404 fallthrough is not an error handler, so `next(error)` after headers were sent only produces `ERR_HTTP_HEADERS_SENT` noise.

### 5. `safeCatalogPage` — `packages/server/src/routes/jellyfin/library.ts`
Add near `lookup()` (~line 47):
```ts
async function safeCatalogPage(
  ctx: JellyfinRequestContext,
  catalog: Parameters<JellyfinService['getCatalogPage']>[0],
  opts: Parameters<JellyfinService['getCatalogPage']>[1],
  what: string
) {
  try {
    return await ctx.service.getCatalogPage(catalog, opts);
  } catch (error) {
    logger.error({ err: error instanceof Error ? error.message : String(error), catalog: catalog.id, type: catalog.type }, `catalog fetch failed in ${what}`);
    return { items: [], hasMore: false, capped: false };
  }
}
```
(Import the `JellyfinService` type from `@aiostreams/core` if needed for the parameter types; or type `catalog` as `Awaited<ReturnType<JellyfinService['getCatalogs']>>[number]` and `opts` as `{ startIndex: number; limit: number; search?: string; genre?: string }`.)

Replace every direct `ctx.service.getCatalogPage(` call in library.ts with `safeCatalogPage(ctx, …, '<route>')`:
- `handleItemsQuery` view/genre branch (~line 333) → `'Items by view'`
- `handleItemsQuery` recursive crawl (~line 377) → `'Items recursive'`
- `/Items/Latest` with ParentId (~line 429) → `'Latest by view'`
- `/Items/Latest` fan-out inside `lookup` (~line 447) → `'Latest'` (keep the `lookup` wrapper too)
- `Similar` (~line 738) → `'Similar'`
- `Recommendations` (~line 771) → `'Recommendations'`; then remove the try/catch added in commit 672b2a72 since the helper covers it.
