# Plan 06-01 — Cheap, scrobble-safe item detail; one Jellyfin limiter

## Why (measured on jf4, 2026-09-08)
- `GET /Items/{movie}` takes 1.5 s / 139 KB because `sendItem` (`library.ts` ~600-670) attaches up to 50 media sources on every detail open (`jellyfinAlwaysAttachSources` defaults true). Every other browse call is ~40 ms.
- `buildMediaSources()` → `resolveStreams(type, videoId)` with `withSubtitles` defaulting to **true** (`service.ts` ~265-345) → `getSubtitles()` → AioMetadata subtitles request. AioMetadata fires its Trakt/Simkl/PMDB check-ins from the subtitles request (see STATE.md 2026-09-08 12:40), so merely opening a movie in Infuse can mark it watched.
- Three limiters bit Infuse in one day (stremio-catalog, static for images, and the item-detail bucket). `index.ts` classifies by path regex with a growing list of exceptions.

## Steps

### 1. Config — `packages/core/src/config/schema/api.ts`
- Change `jellyfinAlwaysAttachSources` default to `false` and update its description: "Attach real media sources on item detail for every client (slow: resolves all streams on open). Normally only clients listed in `jellyfinAttachSourcesClients` get this."
- Add `jellyfinAttachSourcesClients` (string list / comma-separated string, env `JELLYFIN_ATTACH_SOURCES_CLIENTS`, default `"SenPlayer"`): client names (case-insensitive substring match against the MediaBrowser `Client` header) that get media sources on item detail without asking. Follow the existing pattern in this file for list-typed fields; if none exists, store as a comma-separated string and split at use.

### 2. Detail handler — `library.ts` `sendItem`
- Compute `attach = wantsSources || appConfig.api.jellyfinAlwaysAttachSources || clientMatches(ctx.client.name, appConfig.api.jellyfinAttachSourcesClients)` where `clientMatches` is a small helper (lower-case substring match over the list).
- Only when `attach` is true resolve `target` and call `buildMediaSources`. Otherwise leave `item.MediaSources` as built by the DTO (the single stub), which Infuse accepts and then calls `PlaybackInfo` at play time.

### 3. No subtitles on detail — `service.ts`
- `buildMediaSources(type, videoId, opts)` gains `opts.withSubtitles?: boolean` (default `false`) and passes it to `resolveStreams`. The detail path (`sendItem`) uses the default (no subtitles). `playback.ts` `PlaybackInfo` must keep subtitles: find its `buildMediaSources` call and pass `{ …, withSubtitles: true }` so playback still gets subtitle tracks. Verify with `grep -rn "buildMediaSources(" packages/server/src`.
- Note: `resolveStreams` memo key already includes the `withSubtitles` flag, so a detail-page resolution (if it ever happens) and a playback resolution do not collide.

### 4. One limiter for authenticated Jellyfin traffic — `index.ts`, `ratelimit.ts`, `rate-limits.ts`
- Keep `loginRateLimiter` for `LOGIN_LIKE` (when no path credentials) and `stremioStreamRateLimiter` for `STREAM_LIKE` (`PlaybackInfo|MediaSources`).
- Replace the CATALOG_LIKE / ITEM_DETAIL_LIKE / IMAGE_LIKE / static branches with a single `jellyfinRateLimiter` = `lazyLimiter(() => appConfig.rateLimits.jellyfin, 'jellyfin', jellyfinDeviceKeyExtra)` backed by a new `jellyfin: rateLimit({ windowDefault: 5, maxDefault: 2000, envPrefix: 'JELLYFIN', label: 'Jellyfin API' })`. Remove `jellyfinBrowse` and `jellyfinImages` config entries and limiters (added in Phase 5 and the jf6 quick task) — one knob, documented once. Keep the `{ Message }` 429 error middleware.
- Public unauthenticated paths (`System/Info/Public`, `Branding/*`, `QuickConnect/*`) keep `staticRateLimiter` — check `PUBLIC` in `context.ts` for the list and reuse the same regexes (export them from context.ts if needed).

### 5. Build, test, commit
- `pnpm build` zero errors; `pnpm --filter ./packages/core test` green (53).
- Commit: `perf(jellyfin): attach media sources only on request/SenPlayer, no subtitle fetch on detail; single device-keyed Jellyfin limiter`. Push `origin release`. No deploy (06-02 deploys jf7).

## Hard rules
- Do not remove `jellyfinAlwaysAttachSources` (Maged may need it for an unknown client); only change its default.
- PlaybackInfo must still return subtitles — check the PlaybackInfo response shape is unchanged by reading `playback.ts` before and after.
